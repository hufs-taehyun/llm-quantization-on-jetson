# 04. 실제 양자화 파일로 기기에서 실행: 속도·메모리·전력과 정확도 — 실행 전 계획 (2026-11-19)

## 왜 하는가
실험 [02](../02_llm_quant_confidence/)는 가중치를 줄였다가 되돌린 값(fake quant)으로 **정확도만** 쟀다.
실제 커널(torchao)은 이 Orin에서 느려지거나 실패해서, "줄이면 무엇을 얻는가"에는 답하지 못했다.
여기서는 기기용 실행 엔진(llama.cpp, CUDA)으로 **실제로 줄어든 파일**을 돌려 얻는 것과 잃는 것을 함께 잰다.

## 질문
1. F16 대비 8비트·4비트 파일은 생성 속도, 프롬프트 처리 속도, 메모리, 전력(토큰당 에너지)이 얼마나 다른가?
2. 같은 파일들의 정확도와 확신 오답은 얼마나 다른가?
3. 02에서 본 방향(8비트는 원본과 같음, 4비트는 정확도 하락, 확신 오답 변화는 모델마다 다름)이 실제 파일에서도 같은가?

## 모델과 파일
- Qwen2.5-1.5B-Instruct, SmolLM2-1.7B-Instruct (02에서 쓴 것과 같은 가중치, Jetson `~/llm`)
- llama.cpp의 `convert_hf_to_gguf.py`로 F16 GGUF를 만들고, `llama-quantize`로 **Q8_0, Q4_K_M**을 만든다.
- **Q4_K_M은 02의 W4(그룹 128 RTN)와 다른 방식이다**(블록 단위 스케일, 일부 텐서는 더 높은 비트). 따라서 3번은 "같은 숫자의 재현"이 아니라 "방향이 같은가"만 본다.
- llama.cpp 커밋 해시, 각 GGUF의 크기와 SHA-256을 기록한다.

## 측정 1: 속도·메모리·전력
- 도구: `llama-bench`, GPU에 모든 층(`-ngl 99`), 프롬프트 512토큰(`-p 512`), 생성 128토큰(`-n 128`), 5회 반복(`-r 5`)
- 구성: 모델 2 × {F16, Q8_0, Q4_K_M} = 6개. 순서는 모델마다 F16 → Q8_0 → Q4_K_M, 구성 사이 60초 쉼
- 기록: 프롬프트 처리 tok/s, 생성 tok/s(평균·표준편차), 파일 크기, 실행 중 사용 메모리 최댓값(tegrastats RAM, 시작 전 값과의 차이), VDD_IN 평균(보드 전체), 시작·끝 온도, 과전류 보호 횟수(oc3_event_cnt) 변화
- 토큰당 에너지 = 생성 구간 평균 전력 ÷ 생성 tok/s. 구간을 나눌 수 없으면 실행 전체 평균 전력을 쓰고 "근사"라고 적는다.
- 전원 모드 25W, 다른 작업 없음. 화면(GNOME)은 켜진 상태 그대로 두고 그 사실을 적는다.

## 측정 2: 정확도·확신 오답
- 데이터: ARC-Challenge test 1,144문항(02와 같은 문항). 층 선택이 없으므로 validation은 쓰지 않는다.
- 프롬프트: 02와 같은 문장을 HF 토크나이저의 채팅 템플릿으로 만든 **문자열 그대로** `llama-server`의 `/completion`에 보낸다(서버 쪽 템플릿 적용 없음).
- 채점: 다음 토큰 1개의 상위 확률(`n_probs` 100)에서 "A"/" A" … "D"/" D"를 글자별로 합쳐 4개로 정규화. 상위 100 안에 없는 글자 토큰은 0으로 둔다. A~D 확률 질량 평균을 함께 보고한다.
- 지표·통계는 02와 같다: 정확도, 확신 오답률(확신도 ≥ 0.8이면서 오답), ECE, F16과의 판정 일치율, 문항 단위 부트스트랩 10,000회(seed 0).
- 주된 비교(모델마다 2개, 확신 오답 차이에 Holm 보정): Q8_0 − F16, Q4_K_M − F16
- 점검(아무것도 고르지 않음): validation 앞 20문항에서 F16 GGUF의 판정이 02의 PyTorch FP16 판정과 얼마나 같은지 본다. 18/20 미만이면 프롬프트·토큰 처리(BOS 중복 등)를 먼저 고치고 그 내용을 적는다.

## 판단 기준 (고정)
- "더 빠르다 / 느리다": 생성 tok/s 5회 값의 범위가 서로 겹치지 않을 때만. 겹치면 "구분되지 않음".
- 02 방향과 같은가:
  - D1. Q8_0 − F16 확신 오답 차이 구간이 0을 포함한다.
  - D2. Q4_K_M − F16 정확도 차이 구간이 0보다 작다.
  - D3. Q4_K_M − F16 확신 오답 차이의 부호가 02의 W4와 같다(Qwen +, SmolLM2 −). 구간이 0을 포함하면 "구분되지 않음".
- 같지 않으면 그대로 적는다.

## 원칙과 한계
- 결과를 보고 지표·기준·반복 수·문항을 바꾸지 않는다. 추가 분석은 "사후"로 표시한다.
- Q4_K_M 한 가지 4비트 방식만 본다(Q4_0, imatrix 보정 등은 범위 밖). 모델 2개, 데이터 1개.
- 속도는 한 보드, 한 번의 세션에서 잰 값이다. 전력은 보드 전체 기준이다.
- 빌드나 변환이 이 기기에서 실패하면 그대로 보고한다.
