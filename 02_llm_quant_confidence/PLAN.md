# 02. 엣지 LLM 가중치 양자화: 확신 오답과 층별 민감도 — 실행 전 계획 (2026-11-17)

## 질문
Jetson Orin Nano(8GB)에서 Qwen2.5-1.5B-Instruct를 PyTorch로 가중치 양자화할 때,
1) INT8·INT4에서 정확도와 **확신 오답**(높은 확신으로 틀린 답)은 어떻게 변하는가?
2) 그 변화는 **어느 층·어느 모듈 종류**에서 오는가?
3) 민감한 층만 INT8로 두는 혼합 정밀도로 INT4의 손실을 얼마나 줄일 수 있는가?
4) 실제 INT8·INT4 커널에서 속도·메모리·전력은 얼마나 달라지는가?

## 모델과 데이터
- 모델: Qwen2.5-1.5B-Instruct (Apache-2.0), PyTorch FP16, Jetson GPU
- 데이터: ARC-Challenge (보기 A~D 4개인 문항만)
  - **validation (민감도 진단·층 선택 전용)**, **test (최종 보고 전용)** — 선택 편향을 막기 위해 분리
- 프롬프트: 모델의 채팅 템플릿, 0-shot, "Answer with only the letter"
- 채점: 마지막 위치의 다음 토큰 분포에서 "A"/" A" … "D"/" D" 확률을 글자별로 합쳐 4개로 정규화
  - 예측 = 최댓값 보기, 확신도 = 그 확률. 생성 문장은 파싱하지 않음

## 양자화 (직접 구현, 정확도 측정용)
- 대상: 디코더의 모든 Linear (q, k, v, o, gate, up, down). 임베딩·lm_head는 FP16 유지
- **W8**: 출력 채널별 대칭 INT8, 가장 가까운 값으로 반올림(RTN)
- **W4**: 입력 방향 128개씩 그룹별 대칭 INT4, RTN
- 활성값은 FP16 그대로 (weight-only)
- 구현은 가중치를 양자화 후 다시 FP16으로 되돌린 값으로 바꾸는 방식(fake quant) — 정확도 측정용이며 속도·메모리는 아래 4)에서 따로 잰다

## 민감도 진단 (validation)
- 층별: 디코더 층 i 하나만 W4, 나머지 FP16 → FP16 대비 확신 오답 증가량과 판정 일치율
- 모듈 종류별: q/k/v/o/gate/up/down 중 한 종류만 모든 층에서 W4
- 순위 기준(고정): validation 확신 오답률 증가량, 동률이면 판정 불일치율

## 혼합 정밀도
- validation 층별 순위 상위 k개 층을 W8, 나머지를 W4. **k = 2, 4 (실행 전 고정)**
- test에서 보고

## 최종 비교 (test) — 실행 전 고정
- 구성: FP16, W8, W4, Mixed-k2, Mixed-k4
- 지표: 정확도, 확신 오답률(확신도 ≥ 0.8이면서 오답), ECE(10구간), FP16과의 판정 일치율, 맞→틀·틀→맞 수
- 통계: 문항 단위 부트스트랩 10,000회(seed 0) 95% 백분위 구간, FP16(또는 W4)과의 짝 차이
- 주된 비교 3개, 확신 오답률 차이에 Holm 보정: (1) W8−FP16, (2) W4−FP16, (3) Mixed-k4−W4
- 판단: 차이 구간이 0을 포함하면 "구분되지 않음"(같다는 뜻 아님)

## 실제 커널 측정 (속도·메모리·전력)
- torchao `int8_weight_only`, `int4_weight_only(group_size=128)` 적용 모델과 FP16
- 프롬프트 처리 지연, 생성 tokens/s (128토큰, greedy, 워밍업 뒤 5회 중앙값), 최대 GPU 메모리, tegrastats VDD_IN
- torchao 커널이 이 GPU(sm_87)에서 동작하지 않으면 그대로 보고한다

## 원칙과 한계
- 결과를 보고 지표·기준·k·문항을 바꾸지 않는다. 추가 분석은 "사후"로 표시한다.
- 모델 1개, 데이터셋 1개, 0-shot, RTN만 사용(GPTQ·AWQ 같은 보정 기반 방법은 범위 밖).
- 다음 토큰 확률은 생성 품질 전체를 대표하지 않는다. 전력은 보드 전체 기준이다.
