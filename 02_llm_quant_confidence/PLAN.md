# 엣지 기기 위 소형 LLM 양자화: 정확도와 "확신하며 틀린 답" — 실행 전 계획 (2026-11-17 작성)

## 질문
Jetson Orin Nano(8GB)에서 소형 LLM을 FP16 → 8비트 → 4비트로 양자화할 때,
1) 정확도는 얼마나 떨어지는가?
2) 정확도가 비슷해도 **높은 확신으로 틀리는 답**이 늘어나는가?
3) 속도·메모리·전력은 얼마나 좋아지는가?

## 고정 조건
- 모델: Qwen2.5-1.5B-Instruct (Apache-2.0). FP16 약 3GB라 8GB 기기에서 원본과 비교 가능.
- 실행 엔진: llama.cpp (CUDA 빌드, 같은 커밋으로 고정), 양자화 수준 3가지
  - F16 (기준) / Q8_0 (8비트) / Q4_K_M (4비트)
  - 같은 원본 가중치에서 llama.cpp `llama-quantize`로 직접 변환 (다른 사람이 만든 양자화 파일을 섞지 않음)
- 평가 데이터: ARC-Challenge test 중 보기 4개인 문항 전체 (공개 데이터셋)
- 채점: 프롬프트 끝에서 다음 토큰으로 " A"/" B"/" C"/" D"가 나올 로그확률을 읽고 4개에 대해 softmax
  - 예측 = 확률이 가장 큰 보기, 확신도 = 그 확률
  - 생성 문장을 파싱하지 않음 (채점 오류를 없애기 위해)
- 프롬프트: 0-shot, 세 모델에 같은 문자열, 온도·샘플링 없음

## 지표 (실행 전 고정)
- 정확도
- **확신 오답률**: 확신도 ≥ 0.8 이면서 틀린 문항의 비율 (기준 0.8은 이전 비전 실험과 같은 값)
- ECE (10구간 보정 오차)
- 판정 일치율: F16과 같은 보기를 고른 비율, F16이 맞힌 문항을 틀리게 바꾼 수와 반대 수
- 속도: 프롬프트 처리 tokens/s, 생성 tokens/s (`llama-bench`, 반복 5회 중앙값)
- 메모리: 모델 로드 후 최대 사용량
- 전력: tegrastats VDD_IN, 대기 30초 / 생성 연속 30초

## 통계 (실행 전 고정)
- 문항 단위 부트스트랩 10,000회, seed 0, 95% 백분위 구간
- 8비트·4비트는 F16과의 **짝 차이**로 비교. 구간이 0을 포함하면 "구분되지 않음"(같다는 뜻 아님)
- 주된 비교 2개(Q8_0 대 F16, Q4_K_M 대 F16)의 확신 오답률 차이에 Holm 보정

## 판단 기준
- 정확도 하락이 짝 차이 구간 상한 기준 2%p 이내면 "정확도 유지"
- 확신 오답률 차이 구간이 0보다 위면 "확신 오답 증가"
- 결과를 보고 지표·기준·문항을 바꾸지 않는다. 추가 분석은 "사후"로 표시한다.

## 한계 (미리 적어 둠)
- 모델 1개, 데이터셋 1개, 0-shot.
- 다음 토큰 확률은 생성 품질 전체를 대표하지 않는다.
- 전력은 보드 전체 기준이다.
